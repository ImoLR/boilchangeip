# v2.2.24 — Fachost Seednet：5 分钟确认 + 延迟第二次重拨 + 固定主机密钥

用户 2026-11-25 批准（「可以 我同意」）。背景：11-18…11-25 boil 每天都报 "FACHost reconnect failed"，
但 mmwx DDNS 显示 11-15/16/19/20/23/24 IP 其实换成功了 → (a) 120 s 确认窗口在成功日是假阴性
（旧 IP 消失后按域名 SSH 要等 DDNS + 解析缓存）；(b) 约一半日子真没换成，原第二轮在第一轮截止后
约 20 s 就发，没用。

## 设计

- 确认窗口 120 s → 300 s，每 10 s 轮询一次（同 Tcscloud）。
- 第一轮窗口结束：
  - 换成功 → ✅。
  - 最后一次查询能 SSH 到本机且仍是旧 IP（且厂商没明确返回成功）→ 确实没换：后台等 25 分钟，先查一次
    （最多 3 次，每次隔 10 s）：已变 → ✅（迟到的成功）；仍旧 IP → 第二次重拨 + 5 分钟确认；
    查不到 → ⚠ 未知，不重拨。
  - 不可达 / 未知（含厂商明确返回成功但网络没确认）→ 不重拨；后台 25 分钟后再查一次，报告最终结果
    （✅ 已变 / ❌ 仍旧 IP / ⚠ 仍查不到）。
  - 第二轮窗口后仍不可达 → 再做一次 25 分钟后的迟到检查。每次运行最多 2 次重拨。
- 等待与第二轮在后台任务里跑（`tokio::spawn`），不持有 `CHANGE_IP_LOCK`，不阻塞定时器的逐台循环；
  `CHANGE_IP_LOCK` 只在发 `/re-pppoe` 那一下持有；第二轮实际执行时持有该服务器锁。同一服务器只允许
  一个后台跟进任务。daemon 重启会丢失尚未执行的跟进（只影响当次报告）。
- TG：首条结果为 ⚠ 待确认并说明「25 分钟后…结果另行通知」；跟进完成后再发一条结果（定时任务发到
  通知频道，手动 /change 发回原聊天）。CLI `change` 前台同步等待跟进。
- 主机密钥固定：`fachost_seednet` 新增可选 `known_hosts_path` / `host_key_alias`；配置了就用专用
  known_hosts + `StrictHostKeyChecking=yes` + `HostKeyAlias` + `-F /dev/null`，不匹配 = 尚未就绪；
  不配则保持原 accept-new。发起重拨时主机密钥不匹配 = 确定没执行。
- 其他 Provider（Boil / PQS / Tcscloud）不变。
